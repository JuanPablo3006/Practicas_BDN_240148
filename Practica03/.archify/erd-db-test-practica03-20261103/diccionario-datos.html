Cómo leer la clasificación

El campo SQL es escalar por fila (monovalorado) y simple porque la columna almacena un solo valor. Naturaleza y escala se infieren del nombre y tipo SQL; dominio se toma de ENUM/SET o CHECK cuando existe; de otro modo se expresa el tipo SQL y sus límites físicos. “Almacenado/derivado” describe columnas físicas y expresiones GENERATE; los campos de vistas son proyectados o calculados. No se atribuyen reglas del negocio que el DDL no declare.

NULL: permitido por la columna si no declara NOT NULL.
Omitible al insertar: sí si admite NULL, tiene DEFAULT, AUTO_INCREMENT o es generado.
PK/FK/UK: primaria / foránea / única.
Escalas: nominal (categorías), ordinal (orden), intervalo (diferencias), razón (cero significativo).
Proyectado: columna presentada por una VIEW; puede combinar/cambiar datos.
Índice: estructura para unicidad o búsqueda, no garantiza por sí misma semántica adicional.

Ejemplos sencillos

  • Si tb_users.ID es AUTO_INCREMENT, puede omitirse al insertar y MySQL asigna la clave.
  • Si una columna indica NULL y no tiene DEFAULT, se puede omitir; su valor queda NULL.
  • Una FK user_ID → tb_users.ID exige que el padre exista cuando no admite NULL.
  • Una vista que presenta precio * cantidad muestra un valor proyectado/calculado; no equivale a una columna persistida.
Clasificación semántica orientativa y determinista a partir de DDL; confirmar con reglas de negocio cuando el esquema no las expresa.
